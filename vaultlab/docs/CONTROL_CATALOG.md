# VaultLab control catalog

The authoritative machine-readable catalog is [`controls/vaultlab-controls.json`](../controls/vaultlab-controls.json).

All current controls are release-blocking. They cover authenticated encryption, wrong-credential failure, KDF bounds, parser restrictions, corruption handling, report redaction, production exclusion, recommendation-only agents, prohibited event fields, revision-bound evidence, sanitized signing intent, recovery governance, native-custody readiness, withdrawal policy, release provenance, incident governance, privileged access, ledger integrity, break-glass governance, API/session security, signer ceremonies, assurance-signer gateway conformance, resilience, secret leakage, immutable audit, security exceptions, client integrity, market data, availability, vulnerability remediation, external-assessment governance, privacy minimization, cryptography review, quantum-migration governance, consumer release binding, security disclosure, and third-party risk.

VaultLab v0.13 contains 64 controls. The consolidated platform-policy report records twenty-six aggregate checks and 237,629 evaluated cases, including fixed-purpose signer-gateway identity, v2 challenge and receipt-ID binding, canonical receipt status, source revision, digest, deny-only, transport, replay, rate, and provider-downgrade cases. Aggregate PASS is evidence for review, never a quantum-safety claim, proof of solvency, a provider approval, or permission to perform cryptography, migrate algorithms, generate/export keys, execute signer requests, activate/distribute clients or disclosure programs, onboard providers, execute contracts/payments, issue credentials, share data, execute updates, access devices or raw data, store keys, publish prices or disclosures, trade, execute orders, scan or exploit systems, generate traffic, run chaos, delete data, mutate retention, execute API requests, grant access, start sessions, remediate, patch, restore, fail over, mutate data or balances, hold, contain, revoke, withdraw, sign, deploy, activate custody, or move assets.

Baseline mappings to NIST SSDF, OWASP ASVS, OWASP MASVS, and CCSS identify frameworks for later traceability. They do not claim certification or complete compliance. Exact framework versions, requirement identifiers, applicability, evidence, assessor, exceptions, and retest dates must be added during the independent assurance program.
